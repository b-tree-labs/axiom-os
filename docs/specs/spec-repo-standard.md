# Spec: the repo standard

**Status:** Living. Decision: [ADR-221](../adrs/adr-221-axiom-owns-one-repo-standard.md).
**Implementation:** `axi context` (`src/axiom/extensions/builtins/context/`) and
`axi hygiene stat repo` (`src/axiom/extensions/builtins/hygiene/repo_standard.py`).

This is what every repository built on Axiom contains, so that a person and
their AI assistant, whichever assistant it is, find the same things in the
same places. A change to a required file or section here changes
`REQUIRED_FILES` / `REQUIRED_SECTIONS` in `repo_standard.py` in the same PR,
and the reverse.

## 1. The three layers

| Layer | What it is | Who writes it | What keeps it honest |
|---|---|---|---|
| Tell | `AGENTS.md`: authored sections plus the managed block "Working here with an AI", rendered to every tool's file | The repo's authors, plus Axiom for the block | `axi context sync` |
| Help | Axiom's MCP tools and verbs; the terminal command for each when a tool has no MCP | Axiom | The block names them |
| Check | `axi context check` (pre-commit and CI), `axi hygiene stat repo` | Axiom | Fails or reports with the fix |

## 2. Required files

| File | Where it may live | Notes |
|---|---|---|
| `AGENTS.md` | repo root | Canonical. Edit this one. |
| `CLAUDE.md` | repo root | A symlink to `AGENTS.md`, or a byte-identical copy where symlinks are unavailable. `axi context sync` manages it. |
| Generated tool files | `GEMINI.md`, `.github/copilot-instructions.md`, `.cursor/rules/axiom.mdc`, `.junie/guidelines.md` | Generated by `axi context sync`, committed, never hand-edited (each opens with a DO-NOT-EDIT marker). Codex reads `AGENTS.md` natively. |
| `README.md` | repo root | What the project is, how to start, and a link to the AI guide if the repo has one. |
| `CONTRIBUTING.md` | root, `.github/` or `docs/` | Mechanics: setup, branches, pull requests, commit messages. |
| `LICENSE` | repo root | |
| `CODEOWNERS` | root, `.github/`, `docs/` or `.gitlab/` | Who reviews. |
| `.editorconfig` | repo root | |
| `.gitignore` | repo root | Ignores local state the tools write (`.axi/`, `runtime/`, virtualenvs, run output). |
| `.pre-commit-config.yaml` | repo root | Includes a local hook whose entry is `axi context check` (see §5). |
| CI workflow | `.github/workflows/*.yml` or `.gitlab-ci.yml` | A GitHub workflow declares a top-level `concurrency:` group so a new push cancels the superseded run. |
| `docs/` | repo root | One folder per kind (`prds/`, `specs/`, `adrs/`, `guides/`, ...), per `docs/conventions/doc-standards.md`; `axi hygiene stat docs` audits it. |
| `tests/` | repo root (or `test/`) | Tests named for the behaviour they prove. |

## 3. Required `AGENTS.md` sections (authored)

Each repository writes these itself. The audit matches `##` and `###`
headings loosely, so the wording is the repository's own.

| Section | What it says | Heading the audit accepts |
|---|---|---|
| What this repo is | One paragraph: what it does, for whom, and where it sits in the stack | "What this repo is", "What the project is" |
| What this repo is not | What belongs elsewhere, and where | any heading containing "is not" |
| Where code goes | A table from "I want to..." to a path | "Where code goes", "Where things go" |
| Safety rules | The rules that protect people, data and systems here. A repository whose code acts on the physical world says so plainly and says how. | any heading containing "safe", "rule", "invariant", "never" or "must" |
| How to run and test | The install and test commands, exactly | any heading containing "test" |

The managed block's own heading never counts as one of these.

## 4. The managed block

Between `<!-- axiom:repo-standard:begin -->` and
`<!-- axiom:repo-standard:end -->`. The first line inside is
`<!-- axiom repo standard vN. ... -->`. The text is
`src/axiom/extensions/builtins/context/templates/working-with-ai.md`; the
current version is `BLOCK_VERSION` in `context/standard.py`.

It is written to the assistant, about the person it is helping, in plain
complete sentences, and it covers, in this order:

1. Start from `AGENTS.md`; the authored sections win where more specific.
2. Plan before code, and say the plan back.
3. One small step at a time.
4. Run the tests after each step; never claim success without them.
5. Commit small, with clear messages.
6. Never hand-edit a generated file.
7. Ask before anything irreversible or outward-facing.
8. Never put a secret in the repository; use the Axiom vault.
9. Read gold data, never silver.
10. When stuck, say so and show the error.
11. Explain what was done in plain words, for a non-developer.
12. Axiom's verbs for context, hygiene, memory and secrets, with the terminal
    command for a tool that has no MCP.

Constraints, each held by a test in `context/tests/test_repo_standard.py`:
40 to 70 lines; no Markdown links (the tool files rebase links per directory
depth); every one of the points above present.

Changing the block: edit the template, bump `BLOCK_VERSION`, and say in the
PR what changed for the people reading it. Every adopting repository picks it
up on its next `axi context sync`, and its `axi context check` fails until it
does.

## 5. The Check layer

- `axi context check` exits 1 when a generated tool file is missing or
  drifted, `CLAUDE.md` does not point at `AGENTS.md`, or the managed block is
  outdated or its markers are unbalanced. A repository without the block is
  not failed (it has not opted in).
- `axi context init` installs it as a git pre-commit hook. A repository using
  the pre-commit framework also declares it, because `pre-commit install`
  replaces `.git/hooks/pre-commit`:

  ```yaml
  - repo: local
    hooks:
      - id: axi-context-check
        name: Agent instructions are current (axi context check)
        entry: axi context check
        language: system
        pass_filenames: false
        always_run: true
  ```

- `axi context status` lists findings, each with its fix:
  `context.standard-missing`, `context.standard-outdated`,
  `context.standard-unbalanced`, `context.missing`, `context.drift`,
  `context.conflict`, `context.uninitialized`.
- `axi hygiene stat repo [--repo PATH] [--json] [--strict]` audits §2 and §3,
  the CI concurrency group and the pre-commit hook, and includes the context
  findings. `--strict` exits 1 on any warning, for CI.

## 6. Adopting

- New repository: `axi context init`, then fill the starter's sections.
- Existing repository: `axi context init`. Authored text is kept byte for
  byte; the block is inserted before the first authored `##` section. Then
  `axi hygiene stat repo` and fix what it reports.
- Keeping current: `axi context sync` after upgrading Axiom; commit what it
  changes.
