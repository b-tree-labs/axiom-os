# ADR-245: A source changes its delivery path in six stages

**Status:** Proposed (2026-11-09)
**Related:** ADR-177 (an ingest edge is pushed to and pulled from), ADR-182 (never down from our own causes), ADR-197 (a switch is one runner with a gate, a lock budget, a soak and an explicit retire), ADR-244 (only the provisioning layer differs between providers), ADR-246 (every infrastructure change passes one gate)

## Context

A site's instrument data can reach a node by more than one path: a file-share
connector that a person or a script fills, or a collector on the site that
pushes through an ingest edge (ADR-177). Sites start on the first and should
end on the second, because a file share depends on a person or a script, has
no delivery receipt, and cannot say that a source has gone silent.

Changing the path is where readings get lost or counted twice. Bronze
deduplicates by row hash, and the hash includes the schema reference, so the
same reading delivered by two paths that use different schemas lands twice
and nothing complains. A switch made in one step has no evidence that the
new path delivers everything the old one did, and no easy way back.

## Decision

**Every source changes its delivery path in the same six stages, and the old
path stays usable until the new one has proved itself.**

![Diagram titled "A source changes its delivery path in six stages". Six stages run left to right: 1 Ready (host, network, keys, channels), 2 Shadow (test data to a separate connector), 3 Overlap (both paths, reconciled), 4 Switch (new path is source of record), 5 Fallback (old path kept, unread) and 6 Retire (old connector retired; bytes kept). If stage 3, 4 or 5 fails, the source rolls back to the old path. A note says overlap must be able to fail: same schema, no reading twice.](../assets/diagrams/source-cutover-stages.png)

*Figure: the six stages. Generated by `scripts/diagrams/infra_portability_diagrams.py`.*

| Stage | What happens | Passes when | Rollback |
|---|---|---|---|
| 1. Ready | Host, network, keys and channel list confirmed | The collector reaches the edge outbound; nothing inbound is needed | Nothing changed |
| 2. Shadow | The collector sends test data to a separate connector | Readings match a known sample | Remove the connector |
| 3. Overlap | Both paths deliver for a declared period (default 7 days) | Every channel and time window agree, and no reading is counted twice | Stop the collector; the old path continues |
| 4. Switch | The new path becomes the source of record | The gate in ADR-246 passes, and the site can see its delivery status | The old path becomes the source again |
| 5. Fallback | The old path stays available, unread, for a declared period (default 7 days) | No gaps, and the collector recovers from a forced network outage without loss | Resume reading the old path |
| 6. Retire | The old connector is retired; its bytes are kept | The site confirms, and the expected-feed check now watches the new path | Reinstate the connector |

Rules:

- **The new path uses the old path's schema reference**, or the overlap
  reconciliation maps one to the other explicitly. Otherwise the same reading
  lands twice.
- **The overlap reconciliation must be able to fail.** It is rehearsed once
  with a deliberately missing window, and it must report that window.
- **Each stage runs on the switch runner (ADR-197)**, with its pass condition
  as the declared probe.
- **Retiring a path for instruments does not retire it for people.** A file
  share that people use for documents keeps that role.

## Options considered

- **Switch in one step.** It lost because there is no evidence the new path
  is complete, and the way back is a manual restore.
- **Run both paths for good.** It lost because two paths for one source
  double the work of every reconciliation and hide which one is the record.
- **Overlap without a reconciliation that can fail.** It lost because a
  reconciliation that has never failed has not been shown to detect anything.

## Consequences

- A cutover takes at least the overlap plus the fallback period per source.
  Sites can move in parallel, but each one passes the stages on its own.
- The schema reference becomes part of a collector's contract with its site.
- A delivery status a site can see becomes a precondition for the switch,
  since the old path's receipts go away with it.
